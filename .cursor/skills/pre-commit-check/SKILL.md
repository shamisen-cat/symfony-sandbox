# Pre-commit check

Run these steps in order from the project root. Skip this check when the changes touch only documentation or `.cursor` configuration files.

## Steps

1. Fix code style.

   ```bash
   vendor/bin/php-cs-fixer fix
   npx prettier --write .
   ```

   If the changes include files generated by a Flex recipe that the user wants to review as generated, do not mix formatting into the same diff; run `vendor/bin/php-cs-fixer fix --dry-run --diff` and `npx prettier --check .` instead and report the changes it would make.

2. Run static analysis.

   ```bash
   vendor/bin/phpstan analyse
   npx eslint
   ```

3. Run the tests.

   ```bash
   vendor/bin/phpunit
   ```

4. Restore `config/reference.php`, which step 3 regenerates without the `when@dev` sections.

   ```bash
   bin/console cache:clear
   ```

   Do not pass `--env=test`. Confirm with `git status` that `config/reference.php` has no changes left, unless the work itself changed bundles or configuration and the dev-generated diff is intended.

## Failures

- Run all steps even when one fails, so the report covers every problem at once
- Fix failures caused by the current changes, then run the check again
- For failures unrelated to the current changes, report them and ask before fixing

## Report

Summarize the result of each step, including the files the fixes changed.
